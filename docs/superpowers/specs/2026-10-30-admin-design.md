# APOWER 官网与运营后台

用户要求在已有 Debian 13、2 核/2GB/50GB 服务器一起部署官网和产品/资讯管理后台，并于 2026-10-30 选择“按推荐方案直接做”，授权采用常规方案、不再等待设计问答。

## 目标及边界

- 保留 Next.js、现有官网设计、手机布局、中英文和已有资料；GitHub Pages 静态测试站继续工作。
- `/admin/` 提供登录、产品/资讯新增编辑、图片上传、草稿、发布、下架、回收站及恢复。运营无需改代码，发布后服务器官网即时展示。
- 产品保留现有四类、图片/配色/参数/详情图；资讯包含中英文标题、摘要、正文、封面/正文图及发布时间。
- 管理员可创建独立运营账号、禁用账号、重置密码、导出内容备份；运营不管理账号。首次登录强制改密。不做审批流、商城、付款、询盘邮件或页面装修系统。

## 方案（由实现方选择）

沿用 Next.js，增加独立 `runtime/` 动态入口，复用现有模板；数据库使用 Node 24 的 SQLite，上传文件存储在发布目录之外。相较独立大型 CMS，内存和维护成本更低；相较改造原静态入口，不影响现有 GitHub Pages。代价是管理功能只覆盖本次明确范围，GitHub Pages 不会实时同步运营数据。

## 安全与数据

- 服务仅监听本机，由 Nginx 代理；非 root 应用用户；HTTPS 后才开放后台登录。
- scrypt 密码散列、随机 session 及数据库内 token 散列；HttpOnly/Secure/SameSite cookie，12 小时到期；退出、改密、禁用可撤销会话；持久化登录限速、同源检查。
- 图片限 8MiB，解码并重新编码成 WebP，不接受 SVG/HTML；随机文件名，隔离上传路径。拒绝任意外部或穿越文件路径。
- 服务端字段校验、参数化 SQL、版本号防止覆盖并发修改、删除可恢复；记录操作审计，不记录密码。
- 数据和上传独立持久目录；每日一致性 SQLite 备份和上传归档，保留最近 7 天。备份仍在同一服务器，后续可增加异地备份。
- 初始凭据随机生成，私密本地文件交付，不进 Git、不复用服务器密码；不更改用户 root 密码或已有 SSH 设置。

## 验收

匿名写入/跨域写入/弱密码/错误文件/越权被拒绝。运营完成创建→上传→草稿不可见→发布可见→修改→下架→删除→恢复；重启后持久化；新产品在首页/系列/详情一致，资讯中英文列表/详情/站点地图一致。原静态构建、单测和桌面/手机布局回归通过；真实 HTTPS 服务器完成登录与发布闭环。若证书、端口等外部条件不满足，明确报告并保持后台不通过明文开放。
