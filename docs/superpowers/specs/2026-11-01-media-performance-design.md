# 官网媒体加载优化

用户在测速结论后要求直接处理。采用已提出的轻量方案，不改视觉设计、字体、图片清晰度或 CMS 功能，不购买 CDN/带宽，不改 DNS 或本机网络。

## 已证实的问题

生产首页冷加载约 21 秒已下载约 5MB，其中约 3.3MB 为屏外背景视频。视频 `preload="none"` 被挂载后的 `play()` 绕过。屏外可持续发展背景图约 489KB 由 CSS 立即加载；公开图片与字体为 `max-age=0`。GitHub 对照约 5 秒完成相同初始资源。路由器两路 DNS 仍偶发返回新旧地址，此项无控制台权限，不能用应用发布冒充修复。

## 方案

- 保留现有 Next.js/React。背景视频初始只输出原有海报，进入视野且允许动态效果时挂载视频并静音循环播放；离开视野暂停，用户手动暂停不被滚动撤销；减少动态效果时保留静态海报。无 IntersectionObserver 时保持兼容回退。
- 原 CSS 背景改为原图的绝对定位原生 lazy 图片，保持原先 cover、居中、尺寸、文字与动画；无需 JS 也可展示。
- 只为服务器版 `/media/`、`/fonts/` 的成功公开文件响应配置 `public, max-age=86400`，不使用 immutable；后续替换同名静态素材需换文件名/版本参数。CMS 图片使用现有唯一文件名，不变；页面、后台、API 不获得此缓存策略。

## 取舍

暂不新增图片处理/CDN 服务，也不更换域名。先消除不必要首屏流量和重复请求；2Mbps 套餐与跨境线路的物理上限仍存在，不能承诺所有网络即时打开。较短的 24 小时静态缓存兼顾重复访问和部署更新，不缓存运营内容列表。

## 验收与发布

单元测试证明屏外不挂视频、进入视野启用、减少动态效果与原弹窗保持可用；真实 Chrome 验证播放/暂停、手机/桌面及原布局。生产构建后验证图片/字体缓存、缺失文件、页面和认证接口。复制旧发布到新目录、保留数据库/上传/环境变量，先在备用端口健康检查再切换，失败回退；GitHub Pages 的 main 不发布。
